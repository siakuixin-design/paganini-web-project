# 节奏谱面与音频校对

游戏使用 `assets/audio/game/` 中已有的四段 MP3，不替换作品。谱面 JSON 采用统一结构：

```json
{
  "schemaVersion": 1,
  "audio": "practice.mp3",
  "difficulty": "Medium",
  "chartType": "simplified-onset-game",
  "scoreTranscription": false,
  "decodedDurationSeconds": 38,
  "manualOffsetSeconds": 0,
  "events": [{"t": 1.347, "lane": 0}]
}
```

`t` 是录音起点之后的秒数，`lane` 为 J/K/L 三条游戏轨道（0/1/2）。这些是录音起音的简化选择，轨道编排不表示原作音高或指法。**不是原曲乐谱，也不是自动转谱准确性承诺。** 游戏按键的三种吉他反馈音为 E3/A3/D4；不宣称这些反馈还原录音中每个音。

## 本次实际检查

| 录音 | 完整解码时长 | 音符数 | 理论最高分 | 80% 通关线 |
|---|---:|---:|---:|---:|
| practice.mp3 | 38 秒 | 40 | 4,000 | 3,200 |
| concert.mp3 | 45 秒 | 41 | 4,100 | 3,280 |
| concerto-no1-finale-excerpt.mp3 | 53 秒 | 58 | 5,800 | 4,640 |
| guitar.mp3 | 45 秒 | 46 | 4,600 | 3,680 |

四个文件均完成 FFmpeg 全文件解码。185 个谱面事件的时间严格递增，轨道有效，且全部位于实际解码时长之内。采用 22,050 Hz 单声道、1024 点 Hann 窗、512 点步长的正向对数频谱变化量，检测较明显的局部起音。每个事件都距附近检测起音不到 135 毫秒；各曲距离中位数约为 23、23、0.4、23 毫秒。完整机器结果在 `rhythm-audio-audit.json`。

这是可重复的**音响起音接近度检查**。它不能证明节拍重音、乐句位置、音高或完整原谱正确。持续音、弱音和装饰音仍需戴耳机人工试听。为避免未经试听的“修正”，本次保留已有事件时间与轨道。

运行音频检查（Python 3、NumPy、FFmpeg）：

```sh
cd /workspace/paganini-web-project
python3 tools/analyze-game-audio.py --output docs/rhythm-audio-audit.json
```

## 人工校正

1. 在浏览器开始游戏，使用有线耳机核对判定线与听到的起音；蓝牙设备可能带来明显输出延迟。
2. 若整首固定偏早/偏晚，使用游戏提供的校准偏移；该值只补偿设备与人的响应，不改变录音或分数规则。
3. 若只有个别事件错误，在对应 JSON 的 `events[].t` 中调整秒数；若需要改变玩法，可修改 `lane`。
4. 谱面必须保持严格时间顺序，`lane` 仅可为 0、1、2，所有时间都必须小于解码音频时长。
5. 修改后重新运行音频检查，并实际从头完成一次游戏、暂停/继续及结算检查。

每个音符最高 100 分；通关线由音符数量动态计算。录音播放结束时必须结算所有未判定事件，不能延续不存在的歌曲时间。

## 判定、暂停与资源管理

`assets/js/rhythm-mini.js` 将录音完整解码为 AudioBuffer，用同一 AudioContext 时钟计算录音位置、音符位置和按键误差。暂停时保存录音位置并停止 BufferSource；继续时从保存位置新建 BufferSource，因此不会以墙上时间累计暂停时长。后台切换会暂停，不会清空本轮成绩。切换乐器、离开页面或静音时停止相应音源。

Medium 判定窗口按绝对时间误差计算：PERFECT ≤75ms、GREAT ≤150ms、GOOD ≤240ms，其外为 MISS。漏过的谱面音符计入 MISS；没有对应音符的空按中断连击，但不虚增谱面音符数或理论最高分。最高分始终为有效音符数 ×100，通关线为 `ceil(最高分 ×0.8)`。旧版 `passed-v2` 记录不会绕过新版通关。

J/K/L 的吉他反馈由项目已有 C4 木吉他采样以 `2^((midi-60)/12)` 速率播放：E3/MIDI52、A3/MIDI57、D4/MIDI62。小提琴反馈使用现有 C4 小提琴采样，三轨反馈为 C4/E4/G4。只有采样请求或解码失败时，才用相同目标频率的合成三角波备用音。所有反馈只作三轨操作提示，不表示录音旋律转写。

可重复的计分与谱面单元检查：

```sh
node tests/rhythm-core.test.cjs
```

浏览器集成可使用 `.rg-wrap.paganiniGame.getState()` 读取状态、录音位置、各判定数、最高连击和采样加载情况。此接口不提供跳时、自动击中或修改计分的生产后门。浏览器测试可以创建短录音和独立短谱面的测试关卡，再用真实音频时钟进行按键、暂停、重试和结束验证。
